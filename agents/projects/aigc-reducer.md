# 降 AIGC 率工作台

把「一眼就是 AI 写的」中文改写成读起来像具体的人写给具体读者的文字，
**同时用一层保真护栏保证数字、引用、引文、术语和段落结构不被改动**。

不是套壳的「同义词替换器」。整条链路是可测量的闭环：

```
输入 → 本地体检（11 项风格指标 + 29 条规则）→ 分段并发改写 → 保真校验
     → 复检（指数降了吗？）→ 没降就把最差的几段连同实测诊断再改一轮
     → 事实核查（改写稿有没有原文没有的事实、有没有改动作者结论？）→ 收敛
```

Word 文档走同一条管线，前后各多一步：

```
.docx → 解析段落（判定哪些可改写）→ ── 同一条管线 ──→ 文字写回原文档 → 下载 .docx
```

每一段都有独立裁定：**保真校验不过、或改完本段指数反而升高，就退回原文**。
所以整条流程是单调不劣的——最坏情况下输出等于输入。

最后一步「事实核查」不是装饰。它不是规则，是一次额外的模型调用，专门找那些
**规则永远抓不到的东西**——实测中就抓到过模型凭空写出「一学期后」这种原文从未
交代的研究时长。详见下面的「事实核查」一节。

---

## 两种用法

| 方式 | 适合 | 产出 |
|---|---|---|
| **导入 Word**（推荐） | 论文、报告、已有成稿 | 一键改写并**下载排版无损的 .docx** |
| **粘贴文本** | 片段、草稿、临时试 | 改写后的纯文本，可复制或导出 Word |

Word 方式只替换正文段落的**文字**，其余一切字节原封不动：表格、图片、公式、
页眉页脚、编号、脚注、批注、样式全部保留。表格按数据对待，不做改写。

## 先说清楚一件事

本项目的 `AI 味指数` 是**本地的风格启发式代理**，**不是**知网 / 维普 /
PaperPass 那类商用 AIGC 检测器的输出，两者数值不可互相换算。

商用检测器内部是大模型分类器，同一段文本在不同时间、不同版本上都会给出不同
分数。维基百科 WikiProject AI Cleanup 维护的《Signs of AI writing》明确不建议
把这类分数当作判定依据，理由有三条：

1. 检测工具优于随机猜测，但错误率不可忽视——改写、标记符号、空格变化、
   以及训练中未见过的新模型都会干扰结果；
2. 人类判断同样有限，普通人辨别大模型文本的能力接近随机猜测；
3. 人类书写正在被大模型影响而趋同，检测难度持续上升。

所以本工具优化的是**已被公开研究反复验证与检测器输出相关的风格信号**：
句长突发度、模板腔密度、标点多样性、段落均匀度、词汇重复度等。风格指标显著
改善意味着文本更接近人类写作的统计特征，但这**不构成对任何具体检测器结果的
承诺**，也无法承诺。

同样要说明的是：工具能保证的只有「数字、引用、引文、术语没被改坏」这类
**可机械校验**的东西。至于「改写稿有没有多出一个原文没有的事实」——数字类由
护栏兜底，**定性类由「事实核查」那一步交给模型判断并报给你**，而模型自己也会
看错，所以最终的判断责任在你。改写后的立场是否还是你的、语气是否合适，也需要
你自己通读一遍。涉及学术诚信与署名的判断，由署名人负责。

## 三个功能

### 导入 Word（一键）

拖入 `.docx` 后界面会先给出解析结果，**花钱之前你能看到会改什么**：

```
正文段落总数   9
其中可改写     4
标题（不改写）   2
过短（不改写）   1
空段落         1
非中文段（不改写） 1
表格          1 个 · 4 段文字（按数据对待，不改）
```

判定规则：

| 段落类型 | 处理 | 原因 |
|---|---|---|
| 正文散文 | **改写** | 目标 |
| 标题 | 跳过 | 标题不该被改写。判定用样式名 + 样式 ID + `outlineLvl` 三层兜底，兼容中文模板的「标题 1」「第一章」 |
| 表格内文字 | 跳过 | 表格是数据不是散文 |
| 文本框 / 页眉页脚 / 脚注 / 批注 | 跳过 | 不在 `body.paragraphs` 里，天然不动 |
| 少于 12 字 | 跳过 | 改写的收益抵不上风险 |
| 纯公式 / 编号 / 英文 | 跳过 | 没有中文可改 |
| 空段落 | 跳过 | — |

改写完成后下载的 .docx 与原文件**段落数、表格数、表格内容、标题文字、样式完全一致**，
只有被改写的段落文字变了。

### 体检（不消耗模型额度）

粘贴文本 → 点 **只体检**。输出 11 项指标的实测值、可疑度、本地诊断，
以及命中了规则库里的哪些模式。

### 改写

选体裁、强度、目标指数、最大轮数 → 点 **开始降 AIGC**。
右侧实时显示进度流，结束后给出：

- 指数前后对比（含每项指标的 `前 → 后`）
- **事实核查结果**（如果有）——红色卡片置顶，带段落号与判断理由
- 逐段对照，**句级 diff**：<del>删除</del> 与 <ins>新增</ins> 直接标在原文/改文上
- 每段的状态标签：`已改写` / `退回原文`（附退回原因）/ `跳过`（附跳过原因）
- 保真提示与整体警告

顶部还有 **复制结果 / 下载 .txt / 再改一轮**。

### 规则库

点右上角 **规则库** 可以看到全部 29 条规则的诊断、建议、中文反例与改法。

## 指标体系

指数是 11 项子指标可疑度的加权平均（权重见 `app/detect.py` 的 `METRIC_META`，
标定锚点见 `ANCHORS`）。

| 指标 | 方向 | 权重 | 说明 |
|---|---|---|---|
| 模板腔密度 | 越低越好 | 0.22 | 规则加权命中密度。与检测器输出相关性最强的一类。 |
| 句长突发度 | 越高越好 | 0.16 | 句长变异系数。人写作长短交错，模型倾向输出等长句子。 |
| 高频 AI 词密度 | 越低越好 | 0.12 | 「赋能/抓手/闭环/不可或缺」的密度。 |
| 标点多样性 | 越高越好 | 0.10 | 标点类别的香农熵。只用逗号句号时上限是 1.0。 |
| 显性连接词密度 | 越低越好 | 0.08 | 「因此/此外/首先」的密度。过高说明句间关系靠标注而非写出来。 |
| 段落长度均匀度 | 越高越好 | 0.08 | 段落长度变异系数。 |
| 短语重复率 | 越低越好 | 0.06 | 重复出现的 6 字片段比例。 |
| 句首重复率 | 越低越好 | 0.05 | 相同两字开头的句子比例。 |
| 短句比例 | 越高越好 | 0.05 | 15 字以内句子的占比。 |
| 第一人称密度 | 越高越好 | 0.02 | 权重很低：学术写作本来就可能不用第一人称。 |
| 具体信息密度 | 越高越好 | 0.02 | 数字密度，作为「具体性」的粗略代理。 |

**指标会按可用信息自动剔除**，而不是硬猜：句子少于 5 句就不算突发度，
段落少于 3 段就不算段落均匀度，标点少于 5 个就不算多样性。剔除后权重自动
归一化，所以短文本不会因为「段落太均匀」被冤枉。

### 实测分离度

| 样本 | 指数 | 判定 |
|---|---|---|
| 人类写的技术随笔 | 7.2 | 很像人写的 |
| 人类写的学术段落 | 34.6 | 偏自然 |
| 典型 AI 生成的报告段落 | 72.0 | 明显 AI 味 |
| 「随着…的快速发展…综上所述…赋能」类段落 | 84.1 | 强 AI 味 |

人类文本（7.2 / 34.6）与 AI 文本（72.0 / 84.1）之间没有重叠。这四个样本是人工
挑的，只能说明指标在这几类文本上方向正确，不构成标定质量证明。

## 规则库

规则骨架来自 [blader/humanizer](https://github.com/blader/humanizer) v3.0.0
（MIT，46k star），其 25 条模式又源自维基百科
[Signs of AI writing](https://en.wikipedia.org/wiki/Wikipedia:Signs_of_AI_writing)。
原文是英文写的，但作者明确指出识别逻辑基于**写作模式**而非词汇表，模式本身
语言无关。本项目做的是把 25 条模式落成中文可执行的正则与词表，并补上中文特有
的几类。

| 类别 | 内容 |
|---|---|
| A 摆架子而不陈述 | 不是X而是Y、单句收尾、伪深刻、铺垫开场、反驳不存在的对手 |
| B 按规律押节奏 | 强行三连、句首重复、破折号当万能连接词、修饰语叠加、被动与缺主语 |
| C 拔高与借权威 | 模型高频词、拔高意义、含糊关联、空洞的「体现了」、营销腔、借来的权威、回避「是/有」 |
| D 按规律排版 | 装饰性加粗、装饰性标题与 emoji、弯引号 |
| E 聊天与草稿残留 | 聊天机器人残留、知识截止免责、标题重复、写的是上一版 |
| F 中文特有 | 万能总结套话、时代背景开场、四字格堆砌、「的」字长链、语体过度书面化 |

规则的 `strength` 语义与 humanizer 的 *weak alone* 约定一致：
**5 = 出现一次就值得改**（A1–A5、E1、E2），
**3 及以下 = 单独出现不算问题，同段落内多条同时出现才计入**。

### 改写的五条硬约束

写进系统提示词，并且在 `guard.py` 里做机器校验：

1. 不得增加原文没有的事实、人名、机构、数字、日期、地点、引文、来源；
2. 不得删除任何数字、百分比、年份、区间；
3. 不得改动引号内内容、参考文献标记、书名；
4. 不得改变立场、结论和褒贬倾向；
5. 不得在原文没有事实需要时写「首先/其次/最后」，不得用「综上所述」收尾，
   不得用破折号连接分句。

## 事实核查

这是整个工具里唯一**无法用规则实现**的一环，也是最重要的一环。

护栏能验证数字、数值区间、引用、引文、术语没被改动——这些都是可以机械比对的。
但它验证不了「模型凭空补了一个原文没有的定性细节」。实测中就发生过：

> 原文只说「实验组的平均成绩从 72.4 分提升至 85.1 分」。
> 改写稿写成「**一学期后**，实验组平均成绩由 72.4 分升至 85.1 分」。
> 原文从未交代研究时长，「一学期」是模型补出来的。

另一轮里模型还写过「实验组在**单元测验中的答题用时**也短于对照组」——原文完全
没提过答题用时。

这类新增在排版上毫无痕迹，读者（和审稿人）很难发现，但对学术文本是致命的。
所以加了这一步：改写完成后，额外调用一次模型，把原文和改写稿一起给它，让它列出
**改写稿里有、原文里找不到依据的陈述**。

它报两类问题，界面上带不同颜色的标签：

| 类型 | 含义 | 实测例子 |
|---|---|---|
| **新增事实** | 改写稿说了原文没有的事 | 原文只报了平均分，改写稿写「实验组在**单元测验中的答题用时**也短于对照组」；原文从未做过检验，改写稿写「分差在**统计上显著**」 |
| **改变立场** | 把原文的判断加强、削弱或反转 | 原文「具有重要的推广价值」→ 改写「能否推广还需更大范围的重复检验」 |

- 结果在界面上以红色卡片置顶显示，标注**问题类型 + 段落号 + 判断理由**；CLI 也会打印。
- 段落号来自模型返回的 `para` 字段并做过校验，不是「整批都算第一段」。
- 它**只报告，不自动回退**——因为核查本身也是模型，会误报，判断权留给你。
- 默认开启，成本是**每次改写多一次模型调用**（长文按 4000 字分批）。
- 关掉：界面取消勾选「事实核查」，或命令行 `--no-fact-check`。

**实测有效**（真实 DeepSeek，非 mock）：

| 输入 | 结果 |
|---|---|
| 含 3 处编造的改写稿 | 全部抓出：答题用时、设备与师资条件、数据不足以判断 |
| 正常改写稿 | 零误报 |

> 先试过用字符 n-gram 重叠做**确定性**检测（标出改写稿里原文没有的三字组）。
> 实测无效：只要改写幅度一大，几乎所有 trigram 都是「原文没有的」，标出来的是
> 一整句话，等于噪声。区分「编造」和「换了个说法」需要语义理解，所以这一环只能
> 交给模型。详见 `app/prompts.py` 里 `FACT_CHECK_SYSTEM` 上方的注释。

## 保真护栏

`app/guard.py`，段落级调用。**硬校验失败 = 该段退回原文并标注**，
不影响其他段落。

| 校验 | 类型 | 说明 |
|---|---|---|
| 数字 | 硬 | 逐个比对**数值核心**（`43.5%` → `43.5`），丢失即拒 |
| 数值区间 | 硬 | `2019—2023` 不能被拆成 `2019，2023`；换成「2019 年到 2023 年」仍然通过 |
| 引用标记 | 硬 | `[12]`、`[3-5]`、`（张三，2020）`、《书名》 |
| 引文 | 硬 | 引号内内容必须逐字保留 |
| 指定术语 | 硬 | 界面上填写的术语表 |
| 长度比例 | 硬 | 默认 0.55–1.75，超出即拒 |
| 拒绝检测 | 硬 | 模型返回「抱歉/我无法/作为AI」等说明性文字时整段作废 |
| 段落回归 | 硬 | 改写后本段指数反而升高 → 退回 |
| 英文术语消失 | 软 | 只警告，因为可能是有意翻译 |
| 标点漂移 | 软 | 只警告 |

护栏是**确定性**的：同样的输入永远得到同样的判定，不依赖模型，不额外花钱。
它覆盖不了的定性新增，交给上面那一步「事实核查」。

## 接入模型

界面「模型设置」会写回 `.env`，保存即生效。也可以手工编辑 `.env`（需重启）。

| 服务 | LLM_BASE_URL | LLM_MODEL |
|---|---|---|
| DeepSeek（默认） | `https://api.deepseek.com/v1` | `deepseek-chat` |
| 智谱 | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-plus` |
| 通义 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| Kimi | `https://api.moonshot.cn/v1` | `moonshot-v1-32k` |

> **安全提示**：密钥以明文保存在本机 `.env` 中。服务只监听 `127.0.0.1`，

> `sk-1••••••••abcd` 形式的脱敏串。

```powershell

python -m app.cli score  in.txt                          # 只体检
python -m app.cli score  in.txt --json                   # 输出 JSON

python -m app.cli reduce in.txt --genre media --intensity aggressive
python -m app.cli reduce in.txt --keep "双重差分,SBM-DEA" # 术语保护
python -m app.cli reduce in.txt --sample my_style.txt    # 声线匹配
python -m app.cli reduce in.txt --target 25 --rounds 4   # 更激进的目标
python -m app.cli reduce in.txt --no-iterate             # 只改一轮，省钱
python -m app.cli reduce in.txt --no-fact-check          # 跳过事实核查（不推荐）
python -m app.cli reduce in.txt --consistency            # 追加跨段落一致性润色

python -m app.cli rules --verbose                        # 打印规则库
python -m app.cli test                                   # 测试模型连通性
```

`-` 表示从标准输入读、往标准输出写，所以可以接管道。

## 几个设计选择

**为什么不做中文分词？**
指标里的句长、标点、段落、模板腔、词表命中都不需要分词；中文文体计量里字符
n-gram 是标准做法，还避开了分词错误带来的噪声。而 jieba 只有 sdist、19MB，
构建后端在本环境下**实测会卡死**，它带来的唯一收益是一个没人会看的词数统计。
所以直接不引入。结果是所有依赖都是纯 Python 或自带 wheel，安装不需要编译。

**为什么删掉了「低频词比例」这个指标？**
原本想用它近似困惑度（模型倾向选高概率词，所以 AI 文本应该有更少的低频词）。
实测下来信号方向是**反的**：口语化的人类写作只有 `0.02`（本来就用常见词），
AI 学术文本却有 `0.12`，人类学术文本在 `0.06`。它会把**人味最足的那类文本**
推向「疑似 AI」，而且所有样本都饱和在 1.0。真正的困惑度需要 n-gram 语言模型，
也就是要随包发行语料，代价不成比例。所以直接不做，而不是留一个标定错误、
看起来很专业但实际上在帮倒忙的指标。

**为什么段落级裁定只用车 5 项指标？**
一段话只有一两句，突发度和标点多样性在这么短的跨度上完全被噪声支配，用它们
判定会拒掉很多好的改写。所以段落级只用模板腔、高频词、重复率、连接词密度、
短句比例（`detect.LOCAL_METRIC_KEYS`），整篇评分才用全部 11 项。

**为什么 Word 是「只改 run 文字」，而不是「读出纯文本再生成新文档」？**
后者会把样式、编号、图表全丢掉，一份排好版的论文直接报废。所以直接在原文档
对象上改文字：只写 `run.text`，**从不删除 run**，也不碰表格、页眉页脚、文本框。
挂在 run 上的图片、公式、脚注引用因此原样保留。

**段内混合格式怎么办？**
如果一段里有多个格式不同的 run（比如中间夹了一处加粗），新文字会写进第一个
run，其余 run 的文字被清空——**段内局部格式会丢失**。这种情况被标记为
`format_risk` 并在界面上报数，由你决定是否接受，而不是悄悄改坏。

**为什么标题用 `outlineLvl` 判定？**
中文 Word 模板里 `style.name` 是「标题 1」而不是「Heading 1」，只匹配
`Heading` 会漏掉几乎所有中文论文的标题。`outlineLvl` 存在段落属性里、是个数字，
不依赖模板命名，最可靠。三层兜底：样式名 → 样式 ID → `outlineLvl`。

**为什么事实核查用模型而不是规则？**
试过规则：标出改写稿里「原文没有的三字组」。实测无效——改写幅度一大，几乎所有
trigram 都是新的，标出来的是一整句话，清单全是噪声。区分「编造了一个事实」和
「换了个说法」需要语义理解，n-gram 重叠做不到。所以这一环花一次模型调用交给
模型，并且只报给你、不自动处置。

**为什么数字比对只看数值核心？**
`2019—2023 年` 里的「年」属于整个区间；改写写成「2019 年到 2023 年」时
「年」会挂到两个端点上。如果按带单位的完整 token 比对，这种完全正确的改写会被
判成「丢失数字」，而这类误报在真实文档上会频繁触发。代价是「43.5%」丢掉 `%`
而保留 `43.5` 不会被这一步抓到——由数值区间校验和长度校验兜底。

**为什么 `.ps1` 文件是纯 ASCII 的？**
Windows PowerShell 5.1 会用 OEM 代码页（中文系统上是 GBK）解码**无 BOM** 的
文件，`.ps1` 里的 UTF-8 中文注释会被解成破坏语法的字符。这个坑是实测踩到的
（`Unexpected token '}'`）。所以所有中文 UX 文案都放在 Python 层，它显式设置
UTF-8 输出。

**为什么用 `.cmd` 而不只是 `.ps1`？**
很多 Windows 机器默认禁止执行 PowerShell 脚本。`.cmd` 包装器用
`-ExecutionPolicy Bypass` **只对本次调用**放宽策略，不改系统设置、不需要管理员
权限。

**`_boot\sitecustomize.py` 是干什么的？**
两个环境适配，都不是业务代码：

1. 沙箱只允许写项目目录，而 `tempfile.gettempdir()` 指向
   `%LOCALAPPDATA%\Temp`，导致所有落盘到临时目录的操作报 `PermissionError`。
   该补丁把临时根目录钉在项目内。
2. `tempfile.mkdtemp` 在 Windows 上用 `0o700` 建目录，会生成受限安全描述符，
   在沙箱令牌下**同一进程也无法写入自己刚建的目录**。pip 解包每个 wheel 都走
   这条路径，所以 `pip install` 会以 `Errno 13` 失败。补丁改用 `os.makedirs`
   （继承权限）。

所以启动必须带 `PYTHONPATH=项目;项目\_boot;项目\libs`——`run.ps1` 已经处理好了，
请用它启动，不要直接 `python -m app.cli`。

## 已知限制

- **本地指数 ≠ 商用检测器分数**，不可换算，也不承诺任何检测器结果（见开头）。
- **标定锚点是人工在小样本上定的**，不是在大规模标注语料上拟合的。
  语料换了、体裁换了，最优锚点会变。所有锚点集中在 `detect.ANCHORS`，
  便于按自己的语料重新标定。
- **保真和降分是有取舍的。** 约束越严，模型改写越保守，残留的 AI 味指数越高。
  实测同一段文本：约束放宽时能压到 32.3，但会**编造「统计上显著」并改写作者
  结论**；补上禁止改结论的约束后，编造消失，指数只降到 49.6。这个方向是刻意的
  ——宁可少降几分，也不要交出去一份事实被改过的稿子。
- **事实核查会误报也会漏报**。它是模型，不是定理。宁可漏报的提示词设定意味着
  它偏保守；反过来，把正常换词报成新增也有可能。它给的是**复核清单，不是判决**。
- **护栏只能校验可机械核对的东西**。定性新增与立场漂移由事实核查负责，两者都
  覆盖不到的情况（比如语气从客观变成推崇）只能靠你通读。
- **不保护法条、合同、逐字引用类文本**。这类文本请用 `保守` 强度，或者干脆不改。
- **Word 段落的编号与交叉引用**：正文段落被重写后，其中的「如图 1 所示」这类
  交叉引用文字不会被自动更新；图片、图表编号本身不受影响。
- **改写会花钱**。一轮的开销大致是「段落数 ÷ 并发数 × 单段输出长度」，
  事实核查再加一次调用（长文按 4000 字分批，可能是几次）。
- **一致性润色默认关闭**（`--consistency` 开启）。它要把全文再送一遍模型，
  成本翻倍，而且段落多的时候更容易出问题；它做了全程保护——段数对不上或任一段
  没过保真校验就整体丢弃。
- **超过 2600 字的段落**会被按句子切块分别改写再拼回，跨块的行文连贯性会略降。
- 输入没有段落分隔符时，会退回**按句切分**处理，输出变成一句一行。
