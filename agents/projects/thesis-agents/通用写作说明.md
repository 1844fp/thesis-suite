# 通用写作：任意题目 · 任意知识库 · 桌面客户端

> 这份文档说的是**怎么用这套助手写你自己的题目**，而不是写某个特定领域。
> 想先看"一键生成"的整体设计，读 [一键生成说明.md](一键生成说明.md)；
> 这里讲的是它如何做到不挑学科，以及新加的桌面客户端。

## 一、30 秒上手

**双击 `启动论文助手.cmd`** —— 服务在后台起来，界面以独立窗口打开（没有地址栏，
看起来就是个桌面程序）。关掉那个窗口不影响服务。

或者在界面里：

1. **写作** 页签填**题目**和**写作要求**（要求可以留空，但填得越具体越好）；
2. 选**论文类型**（决定章节骨架），字数会自动跟着类型给一个常见值；
3. 点**预检（不花钱）** —— 它会告诉你本地知识库里有没有这个选题的材料；
4. 预检通过就点**开始写作**，几分钟后拿到 `.docx` 初稿和一份生成报告。

也可以完全不开界面，用命令行：

```powershell
.\run_python.cmd -m app.cli kb check --topic "你的论文题目"     # 先预检（不花钱）
.\run_python.cmd -m app.cli thesis --topic "你的论文题目" --genre engineering --words 25000
```

## 二、任意题目：三处隐性耦合都拆掉了

这套系统原先**只会写经管实证那一类文章**。不是题目写死了，而是三处地方偷偷假设了学科：

### 1. 默认章节结构（已改为按论文类型给）

原先无论什么题目，默认都是「绪论—文献综述—研究设计—实证结果—讨论—结论」。
那是经管实证论文的骨架。套到别的选题上立刻不对：

| 论文类型 | 章节骨架 |
|---|---|
| **实证研究型** | 绪论 / 文献综述 / 理论分析与研究假设 / 研究设计 / 实证结果与分析 / 讨论 / 结论与展望 |
| **案例研究型** | 绪论 / 文献综述与理论基础 / 研究设计 / 案例描述 / 案例分析 / 讨论与启示 / 结论与展望 |
| **理论思辨型** | 绪论 / 文献综述 / 理论基础与分析框架 / 主体论证 / 结论与展望 |
| **设计开发型** | 绪论 / 相关理论与技术基础 / 需求分析 / 系统设计 / 实现与测试 / 总结与展望 |
| **实验研究型** | 绪论 / 材料与方法 / 实验结果 / 讨论 / 结论与展望 |
| **调查研究型** | 绪论 / 文献综述 / 研究设计 / 调查结果与分析 / 讨论与建议 / 结论与展望 |
| **文献综述型** | 引言 / 文献检索与筛选 / 研究进展 / 争论与分歧 / 研究展望 |

类型不给就按题目自动判一个（`guess_genre`），判错了用 `--genre` 指定。
**作者显式给的章节永远优先**：开题报告里的章节树 > `--section` 指定 > 类型默认。

### 2. 检查器的词表（已改为跟着类型走）

`app/checks/writing_quality.py` 原先硬编码了一份经管方法名词表（双重差分、PSM、
多期超额收益法……）和金融缺口维度词（估值、折现率、收益分割……）。用在别的学科会**静默失效**：

* 「结果章是否引入了研究设计章未交代的方法」——对一篇材料学论文永远报不出来；
* 「研究缺口是否具体」——只认金融维度的词，于是把
  「该合金在高温下的疲劳寿命缺少实验数据」这种**非常具体**的缺口判成"不具体"。

现在词表按类型取（`app/writing/genres.py` 的 `method_terms` / `gap_dimensions`）。
工科词表里有有限元、消融实验；人文词表里有扎根理论、文本分析。

> **为什么不把所有学科的词并成一张大表**：并集会让"相关研究不足"这类空话轻易命中
> 某个学科的维度词，检查器在最该报的时候反而不报了。词表必须跟着论文类型走。

### 3. 检索永远返回 top-k（已加相关性闸门）

向量检索**永远会返回结果**，哪怕库里一篇相关的都没有。换个题目继续跑，
系统会"写出"一篇引用着一堆无关文献、看起来完整的论文——**这比检索不到更危险**。

实测数据（数据资产库 20 篇，每主题取 10 条）：

| 题目 | 相关/总数 | 判定 |
|---|---|---|
| 数据资产化对企业融资约束的影响研究 | 10/10（1.00） | 可用 |
| 数据要素市场化配置的制度经济学分析 | 10/10（1.00） | 可用 |
| 基于深度学习的遥感图像语义分割方法研究 | 2/10（0.20） | **拦下** |
| 2 型糖尿病患者胰岛素抵抗的临床研究 | 1/10（0.10） | **拦下** |
| 乡村振兴背景下乡村教师专业发展路径研究 | 0/10（0.00） | **拦下** |

判定口径是**本地的、可解释的**：从题目与写作要求里切出核心概念短语，展开成 2~4 字子词，
再看证据文本命中了多少。逐条给出命中了哪些词，不是黑箱。

**刻意不用知识库返回的 `score`。** 第一版想直接卡分数阈值，实测发现尺度不可靠：

```
查询「数据资产 会计确认 计量属性」（相关）  首条分数 0.21
查询「卷积神经网络 图像分割」（完全无关）  首条分数 18.76   ← 比相关的高 89 倍
```

重排模型对跨领域查询会给出发散的量纲。**用一个自己都不稳定的信号做门槛，等于没有门槛。**

## 三、任意知识库：查库 → 试查 → 投料 → 预检

界面 **知识库** 页签，或命令行：

```powershell
.\run_python.cmd -m app.cli kb status              # 馆藏多少、服务通不通
.\run_python.cmd -m app.cli kb list                # 文献清单
.\run_python.cmd -m app.cli kb search "数据资产 估值"   # 试查（不花钱）
.\run_python.cmd -m app.cli kb check --topic "你的题目"  # 按题目预检
.\run_python.cmd -m app.cli kb add 我的文献.pdf 另一篇.pdf   # 投料并入库
.\run_python.cmd -m app.cli kb add --dir D:\我的文献          # 递归投料一个目录
```

### 投料的注意事项（都写在报错里，这里先列一遍）

* 支持 **PDF / DOCX / TXT / MD**；扫描版 PDF 需要先做 OCR，`.caj`/`.nh` 需先转 PDF；
* **只复制、不移动**你的源文件；
* 扩展名不支持的**逐条说明原因**，不会悄悄忽略（"我以为投进去了、结果检索不到"
  是最难查的一类问题）；
* 入库在知识库服务里发生，所以要先把 `E:\AI\thesis-assistant\run.cmd` 跑起来。
  服务没起来时文件已经复制过去了，服务恢复后 `kb ingest` 重新触发即可。

### 生成前的预检是零成本的

一次生成是几十次模型调用。题目与知识库不匹配时那些调用**全部白花**，
产出还会被起草阶段的相关性闸门逐章拦下，最后得到一份空稿。
所以预检放在花钱之前——纯检索 + 本地判相关。

预检不通过时 `thesis` 会**直接停下**并告诉你该补什么，不会开始烧钱。
确实要用当前知识库硬跑，加 `--force`（不推荐，相关章节会因缺证据而写不出来）。

## 四、只写我关心的那几章 / 按要求改写

### 只写某几章

作者最常用的不是"从零生成整篇"，而是**"我只要写第 3 章"**或**"第 5 章我自己写，别动它"**。

界面「写作」页签的**章节**卡片里勾掉不想写的章即可；命令行用：

```powershell
.\run_python.cmd -m app.cli thesis --proposal 开题.docx --chapter 研究设计 --chapter 实证结果
.\run_python.cmd -m app.cli thesis --proposal 开题.docx --skip-chapter 结论
```

按**标题片段**匹配（写「实证结果」就能匹配到「第四章 实证结果与分析」），
黑名单优先于白名单。**匹配不到任何章节时退回"全部都写"**而不是生成空稿——
作者写错章名时，"全都写了"是个可预期的结果，"什么都没写"只会让人困惑。

### 按要求改写

界面「稿件」页签底部有**按我的要求改写**：选一个章节或粘贴一段原文，写清楚要改什么。

```powershell
.\run_python.cmd -m app.cli rewrite -p <项目id> --section "第3章" `
    --instruction "把这一节的机制分析补实，用检索到的文献支撑，不要只描述现象"

.\run_python.cmd -m app.cli rewrite -p <项目id> --find "本文以A股上市公司为样本" `
    --instruction "这一段没有依据，改写成有出处的表述，或直接删掉无依据的断言"

.\run_python.cmd -m app.cli rewrite -p <项目id> --targets '[{"section":"研究设计","instruction":"补上变量定义"},{"find":"…","instruction":"…"}]'
```

三条设计约束：

1. **改写同样只依据证据**，角标越界照样删并记账；
2. **改完产生新版本**，可在「版本」页签对比回退；
3. **段落级改写整段替换**，不拼接。允许"局部替换几句话"会让段落由新旧两种行文拼成，
   语气与指代常常对不上，而这种问题在成稿里极难发现。整段替换改动更大，
   但**改动的边界清晰**，作者对比两版就能看出模型到底重写了什么。

改写完命令行会自动接着跑一次 `writer:references` 重新定稿（角标要连续化、文献表要重建）。

## 五、桌面客户端

```powershell
.\启动论文助手.cmd      # 双击也行
```

它做三件事：

1. 服务没跑就**在后台**起一个（关掉窗口不影响）；
2. **等它真的能响应**再往下走；
3. 用浏览器的**应用模式**（`--app=`）打开，没有地址栏和标签页——看起来就是个桌面程序。
   找不到 Chrome/Edge 就退回默认浏览器（少个壳，功能一样）。

刻意**不**用 Electron/Tauri：一个需要 node 工具链才能跑起来的"客户端"，
在离线或受限环境里只会变成新的故障源。

### 界面结构

| 页签 | 作用 |
|---|---|
| **写作** | 题目 / 写作要求 / 论文类型 / 学位 / 字数 / 开题报告 → 章节勾选 → 知识库预检 → 开始写作 |
| **知识库** | 状态、投料入库、试查、按题目预检、馆藏清单 |
| **运行** | 对已有项目跑完整流水线（验证 / 修复 / 降 AIGC / 格式） |
| **问题** | 问题清单，按严重度排序，需作者判断的逐条列出 |
| **稿件** | 当前稿件 + **按要求改写** |
| **版本** | 版本链与逐段 diff，可回退 |
| **工具** | AI 味体检、参考文献真实性核验、知识库检索、资料目录 |
| **设置** | 模型、对端服务地址、外部核验开关（保存即生效，不用重启） |

## 六、开发中踩到的四个新坑

### 1. `/api/status` 太慢，拿它当探针等于没有探针

启动器一开始用 `/api/status` 判断"服务起来了吗"。它每次要**2.1 秒**
（健康检查两个对端服务 + 列出全部项目 + 导出注册表快照），而探针超时是 2 秒——
**每一次探测都超时**。表现是启动器等满 60 秒后报"启动失败"，
而 uvicorn 日志里明明写着 `Uvicorn running on http://127.0.0.1:8780`。

修法是加一个 `/api/ping`：立刻返回，什么都不查。
**"我活着吗"和"我的依赖都好吗"是两件事，前者必须是零成本的。**

### 2. 浏览器进程继承 stdout，把外层管道一直挂着

启动器打开浏览器时没有重定向 stdio，浏览器**继承了父进程的 stdout**。
而启动器常常是被重定向/管道的（`.\启动论文助手.cmd | ...`、或在 IDE 里跑），
浏览器不退出那个管道就一直不关闭，**外层会一直等下去**——
表现是"启动器卡住不动"，而服务其实早就起来了。

修法：子进程的 stdin/stdout/stderr 全部指向 `DEVNULL`。

### 3. Windows 上有些端口以 WinError 10013 拒绝绑定

实测本机 8798 被拒、8780 正常，而它**不在** `netsh` 报出来的保留区间里
（保留区间只有 5357）。作者看到"服务启动超时"只会以为程序坏了。

修法：启动前先**探一下端口能不能绑**（绑上立刻关），被拒就换下一个并说明换过；
同时把"哪个端口、为什么失败"追加写进日志——原先每次尝试前清空日志，
失败原因就没了，而那正是排查时唯一需要的信息。

### 4. `os.replace` 在 Windows 上会抛瞬时 PermissionError

项目的状态落盘用的是标准的"写临时文件再 replace"原子写法。而 `os.replace`
在目标文件被其它句柄占用时会抛 `PermissionError [WinError 5]`——
占用者通常不是本程序，而是杀毒软件的实时扫描、同步盘、资源管理器预览。

实测代价很大：一次生成结束时恰好撞上，**整条流水线崩在保存状态这一步**，
前面几十次模型调用全部作废。而这类占用是毫秒级的，重试几次就过去了。
现在 `Blackboard.save()` 重试 6 次（递增退避），仍失败则抛出并说明可能原因——
**绝不静默丢状态**：状态没落盘意味着"作者看到的进度"和"磁盘上的进度"不一致。

## 八、这套东西仍然不做什么

1. **不判断你的结论是否正确。** 结论章是依据正文汇总的结构草稿，每条都要你确认。
2. **不代写创新点与致谢。** 任何环节都不生成。
3. **不补全参考文献字段。** 期刊名、卷期、`[J]`/`[M]` 标识缺失就留空并逐条列出。
4. **不做查重与 AIGC 检测。**
5. **知识库里没有的选题，它不会硬写。** 会明确告诉你"写不了，请先补资料"——
   这是设计选择，不是能力不足。
6. **不做学科专属的领域推理。** 它按论文类型的通行骨架组织内容，
   但"这个选题该用什么理论"是你和导师的判断。
