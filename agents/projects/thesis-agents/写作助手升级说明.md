# 论文写作助手 · 升级说明

> **本文记录的是写作助手第一次升级（内置规范 + 13 个写作检查器 + RAG 示例）的内容。**
> 之后写作助手又经历了一轮实质扩展：**从开题报告一键生成整篇论文初稿**，
> 新增研究设计／实证结果／讨论／结论四类章节蓝图、长文分段起草、全篇唯一引用编号、
> 参考文献表自动生成与 .docx 导出。
> 那部分请看 **[一键生成说明.md](一键生成说明.md)**。

本次针对**写作助手**做了三方面实质升级，目标是让产出的文稿达到 CSSCI 级写作规范。

---

## 一、先说清楚"能保证什么、不能保证什么"

你要求"达到 CSSCI 等级甚至以上"。这个目标必须拆开看，否则会是空话：

| 层面 | 能否自动化 | 本助手的做法 |
|---|---|---|
| **写作规范**（结构、段落、论证推进、综述组织） | ✅ 能 | 内置可检验的规范 + 13 个检查器实测 |
| **语言质量**（术语准确、句式得当） | 部分能 | 降低模板腔、避免逐篇罗列、要求长短交错 |
| **学术观点**（创新性、理论贡献） | ❌ 不能 | 明确不代写结论与创新点 |
| **文献真实性** | ⚠ 部分能 | 外部核验（英文可靠，中文需知网） |
| **是否被 CSSCI 录用** | ❌ 不能 | 取决于选题价值与论证深度，不是工具能决定的 |

**结论**：这套助手能可靠保证的是**写作规范层面达标**——结构完整、论证推进、
综述有整合而非罗列、避免模板腔。**它不能也不该替你产出学术观点。**

## 二、方法论从哪来（及其可验证性）

你要求"调用知名论文或学者的方法论"。这里做了一个刻意的取舍：

**只收录学界公认、可公开查证的写作规范框架，不凭记忆引用具体论文的结论。**
原因很直接——我没有那些论文的原文，凭印象引用等于编造，而且无法核对。

| 章节 | 采用的框架 | 出处（可公开查证） |
|---|---|---|
| 引言 | 三语步：确立领域 → 指出缺口 → 占据空间 | **CARS 模型**（Create A Research Space），John M. Swales, *Genre Analysis*, 1990 |
| 文献综述 | 按研究脉络分组评述，而非按作者/时间罗列 | 综述体裁的基本规范 |
| 正文 | 段落"主题句—证据—分析"结构；论证递进而非并列 | 学术写作通行惯例 |
| 研究设计 | 可复现性：数据来源、样本筛选、变量测量、模型设定四件事写到他人可照做 | IMRaD 结构中的 Methods，科技论文通用体裁惯例 |
| 实证结果 | 结果章报告发现、讨论章解释发现，两者分开 | IMRaD 结构的一条通行纪律 |
| 讨论 | 重述发现 → 与既有研究对照 → 解释机制 → 意义与局限 | IMRaD 结构中的 Discussion |
| 结论 | 研究问题 → 主要结论 → 启示 → 局限与展望；**不引入新证据** | 学位论文写作的通用体裁规范 |

每条规范都标明其惯例名与来源，**你可以自行核对**。凡涉及"某篇论文得出什么结论"
这类内容，一律来自检索到的原文（见第四节），不来自记忆。

## 三、三个章节的具体升级

### 1. 引言：CARS 三语步 + 开篇质量

**内置要求**（`app/writing/__init__.py` 的 `INTRODUCTION`）：

1. **三语步齐备且顺序正确**（blocker 级）——缺口那一步必须单独成段，不能被合并进背景；
2. **开篇用可核实的事实**——政策文件名、统计数据、年份、既有结论；
   禁止「随着……的快速发展」这类空转起手式；
3. **缺口必须具体到可检验**——是方法不足、证据不足还是解释不足；
   禁止「研究还不够深入」「相关研究较少」这种无法检验的说法；
4. **不要用文献罗列代替背景**——引言引文献是为说明现状，逐篇介绍属综述的任务。

### 2. 文献综述：禁止「一篇论文半句话」

**这是本次升级的核心**，也是你明确提出的问题。

**要求**：同一主题下的多篇文献必须**合并成一个判断**——先给结论或分歧，
再把若干文献并列作证。形如：

> 多数研究认为X（A, 2020；B, 2021），但C（2022）在Y情形下得到相反结果。

**禁止**：

> ~~A（2020）研究了…。B（2021）改进了…。C（2022）构建了…。~~

另外三条要求：
- **前后必须连贯**：段落之间要有逻辑连接（继承/补充/对立/递进），
  不能连续多段直接以文献引注开头；
- **每段结论先行**：首句应当是这一段的判断，而不是某篇文献；
- **要有评，不能只有述**：每组文献介绍完后必须给评价（共同局限、适用条件、未解问题）。

### 3. 正文：论证而非罗列

- **段落须有主题句与分析**——摆完事实必须解释它意味着什么；
- **论证要推进，不要并列堆砌**——段落之间是递进/因果关系；
- **每个论断都要有依据**（blocker 级）——「显著提升」这类强断言必须紧跟数字、
  图表引用或文献引注；
- **删掉纯结构标记**——「综上所述」「值得注意的是」等不含信息的词。

## 四、13 个可检验的检查器（升级的关键）

**只把要求写进提示词是不够的——那只是给模型一个愿望。**
所以每条要求都配了检查器，写完立刻实测，报出"哪一段、哪一句、实测值多少"。

| 检查器 | 判定口径 | 严重度 |
|---|---|---|
| `check_intro_cars` | 能否识别出缺口语步与研究定位语步 | blocker |
| `check_intro_opening` | 首段是否含可核实事实（年份/制度/数字） | major |
| `check_intro_gap_specific` | 缺口是否含具体维度词 | major |
| `check_intro_no_citation_dump` | 引言中含多引注的句子占比是否过高 | minor |
| **`check_lit_synthesis`** | **逐句一引占比 ≥80% 即判「一篇论文半句话」** | **blocker** |
| `check_lit_coherence` | 是否连续多段以文献引注直接开头 | major |
| `check_lit_critique` | 评价性表述密度是否过低（只述不评） | major |
| `check_paragraph_topic_sentence` | 段首是否直接以引注开头（缺主题句） | major |
| `check_paragraph_analysis` | 含数据的段落是否完全没有解释性表述 | major |
| `check_claim_evidence` | 强断言所在段落是否无任何依据 | blocker |
| `check_body_progression` | 是否连续 3 段以上句数相同（并列堆砌） | major |
| `check_template_connectives` | 模板腔连接词密度 | minor |
| `check_paragraph_variance` | 句长变异系数过低（风格提示） | info |

### 在真实论文上的实测结果

用你的《开题报告四》跑一遍（`tools/realcheck.py`），产出 **20 条**，全部是真问题：

```
check_lit_synthesis          8 条 [blocker]  ← 正是你提的「一篇论文半句话」
check_paragraph_analysis     6 条 [major]    ← 只摆数据没有分析
check_body_progression       1 条 [major]    ← 连续 6 段句数相同（并列堆砌）
check_paragraph_variance     5 条 [info]     ← 句长节奏过于均匀
```

## 五、真实写法示例（RAG 结合）

规范本身不含语感。所以再从你的 RAG 知识库里取**同领域真实段落**作示例，
摆在提示词里当 few-shot——这是你选的"两者结合"。

取的是已入库 20 篇论文的真实片段，带完整 `citation`（作者/年份/章节/页码）。
实测能取到 6~7 条合格示例。

**过滤掉的噪音**（都是实测踩出来的）：
- 参考文献条目（`（8）毛基业、苏芳：《…》《管理世界》…`）——会教模型模仿文献表格式；
- 刊物页眉页脚（`作者简介: 陈晓珊(1989—)…`、`收稿日期: 2024-08-25`）——版式残留；
- OCR 断行碎片——行均长度过短，读起来是断句。

**示例区块里明确写了"严格禁止照抄"**——这些是已发表论文的原句，
照抄构成抄袭，是这功能里风险最高的一点，所以措辞不含糊。

**RAG 不可用时返回空示例并不阻断写作**（规范本身已足以指导写作，示例只是增强）。

## 六、与"降低 AIGC 率"的方向一致

本次升级的写作要求（长短句交错、去模板连接词、论证推进）与降 AIGC **方向一致**，
不是两个互相拉扯的目标：模板腔句子既拉高 AI 味指数，也确实是写作质量缺陷。

但要重申一个实测结论（见 `tools/aigc_pass.py`）：**AI 味指数偏爱长句**。
把一段 158 字压缩到 108 字、表达更简洁后，指数反而从 43.1 升到 59.7。
所以**不要为指数牺牲可读性**。

## 八、本次升级修掉的三个真实缺陷

都不是"代码写错"，而是**设计上的静默失效**，值得记下来：

1. **`writing_quality` 模块忘了在 `app/checks/__init__.py` 里 import。**
   注册靠装饰器在导入时执行，漏了 import **不报错**，只是检查器不存在——
   写作助手的自查环节一个写作检查器都没跑到，表现为"自查通过"。**比报错危险得多。**
   已在 `__init__.py` 里写明这条纪律。

2. **检查器只挂在特定蓝图的 requirements 上，导致通用检查漏跑。**
   文献综述内容常散落在被归类为"正文"的小节里，于是本助手最要紧的
   「一篇论文半句话」检查**根本没执行**。已增设 `UNIVERSAL_CHECKERS`——
   与章节类型无关的检查（逐篇罗列、段落分析、断言依据、模板腔）对所有章节无条件运行。

3. **散文过滤门槛把"数据型段落"误杀。** 中文字占比门槛原为 0.5，
   而数据段（`2021年为183.14亿元，2022年为…`）占比仅 0.34，
   于是最该被抓的"只摆数据不分析"反而检查不到。门槛已降到 0.25。

另外修掉一个误报：「有效」曾被当作强断言词，实测在真论文上命中 3 条全是误报
（`缺乏有效衔接`、`验证其有效性`——是形容词/名词用法）。**误报会毁掉工具可信度**，
已从断言词表中移除。

## 九、局限（如实列出）

1. **不代写结论与创新点。** 这是原则问题，不是能力不足——那是作者的学术判断。
2. **检查器是结构性的，不理解语义。** 它能发现"这段没有分析"，但不能判断
   "这个分析对不对"。后者需要你或导师来读。
3. **示例可能从句子中间开始。** 那是检索分块的边界，不是文本损坏；
   对"体会结构与语气"的用途影响不大。
4. **中文学术写作的规范存在学科差异。** 内置的是通用规范；
   若你所在学科有特定体例（如经济学偏好假设—检验结构），需要按学科调整蓝图。
5. **"CSSCI 等级"无法由工具保证。** 见第一节的能力边界表。
