# 排版整理说明（把格式写回你已有的 .docx）

> 一句话：**正文小四宋体、1.5 倍行距、标题黑体三号、页边距 A4 规范——这类排版属性，
> 现在可以直接写回你手上那份 .docx，而且内容一个字都不会动。**

对应命令：`python -m app.cli docx-format`；界面对应：**工具 → 论文排版整理**。

---

## 一、为什么这件事要单独做，而且要先讲风险

项目里原有的格式整理（`app/format`）**只报不改**。缺口的理由一直写在 README 里：
框架的修复算子是文本变换（精确替换、编号重排），改不了 `w:sz` / `w:spacing` / `w:pgMar`。
硬塞进算子体系只会造出"报可修复但实际改不动"的假承诺。

而写回这件事的风险和文本修改**不对称**：

* 改错一句话，作者读一遍就看得出来；
* **排版写坏，作者可能到答辩前才发现**——因为内容看着是对的，只是打开时提示
  "文件已损坏"，或者标题悄悄变成了宋体而他不确定原本该是什么。

所以这一层不靠"小心操作"，而是把安全性做成**机制**。

## 二、三条硬保证（都写在代码里，不是口头承诺）

| 保证 | 怎么做到的 | 不通过会怎样 |
|---|---|---|
| **① 文字一字不改** | 写回前把全文抽出来（段落 + 表格 + 页眉页脚），写回后再抽一遍逐字比对 | 发现一个字符不同就**判定失败并自动还原** |
| **② 改完还能打开** | 写回后用 python-docx 重新加载，核对段落数 | 打不开就**判定失败并自动还原** |
| **③ 能退回去** | 原地覆盖时先写 `.bak` 备份 | 失败自动从 `.bak` 拷回 |

命令输出里会逐条打印这三项的实际结果（`✅ 通过` / `❌ 不通过（已还原）`），
所以"改好了"这句话是可证伪的。

**输出到新文件时不备份**：原文件根本不会被碰，再丢一个 `.bak` 只是垃圾。
那种情况下失败处理是"删掉写坏的输出"（源文件仍然完好）。

## 三、它改什么、不改什么

**改（都是 OOXML 属性）**：中文字体（`w:eastAsia`）、西文字体（`w:ascii`/`w:hAnsi`）、
字号（`w:sz`，半磅）、行距（`w:spacing` 的 `w:line`/`w:lineRule`）、首行缩进（`w:ind`）、
段前段后、标题加粗（`w:b`）、对齐（`w:jc`）、页面尺寸与页边距（`w:pgSz`/`w:pgMar`）、
文档默认字体（`w:docDefaults`）。

**不改**：

* **表格里的文字**。表格通常要五号/单倍（比正文小一号），统一按正文改反而错。
  报告里会写明跳过了多少段。
* **页眉页脚**。同理，它们不在 `document.paragraphs` 里。
* **文本层的格式问题**（半角标点、中英文之间缺空格、参考文献编号风格、多余空行）。
  那些归文本算子（`run -s fix`），在这一层改会混淆两套职责。
  命令行的复验输出会**把这两类分开报**——"可写回 44 条 → 0 条，
  文本型 69 条 → 69 条"，避免把"还剩 69 条"误读成"这功能没用"。

## 四、怎么用

### 命令行

```powershell
# 1) 先只看差距，不改文件
.\run_python.cmd -m app.cli docx-format 我的论文.docx --check

# 2) 按通用规范整理（原地覆盖，自动留 .bak）
.\run_python.cmd -m app.cli docx-format 我的论文.docx

# 3) 输出到新文件（原文件不动，不给 .bak）
.\run_python.cmd -m app.cli docx-format 我的论文.docx -o 我的论文_整理后.docx

# 4) 照学校模板改（最省事：模板的样式与页面设置会被读出来）
.\run_python.cmd -m app.cli docx-format 我的论文.docx --like 学校模板.docx

# 5) 逐项指定
.\run_python.cmd -m app.cli docx-format 我的论文.docx `
    --body-font 宋体 --latin-font "Times New Roman" --body-size 12 `
    --line-spacing 1.5 --indent-chars 2 `
    --h1-font 黑体 --h1-size 16 --h2-size 14 `
    --caption-size 10.5 --margin top=2.5,left=3,bottom=2.5,right=2.5
```

固定值行距（中文论文常用的 22 磅）用 `--line-fixed 22`。

### 界面

**工具 → 论文排版整理**：选一份 `.docx` → 需要时改几个数 → 点「整理并下载」。
先点「先看差距」可以只读不改。下载下来的是改好的文件，页面上同时显示
"偏差 117 条 → 69 条"、三条验证结果，以及哪些没改。

> ⚠ 界面这个卡片由**服务端 Python 路由**支撑。如果你在加这个功能之前就开着论文助手，
> 需要**关掉窗口重新运行 `启动论文助手.cmd`**（浏览器刷新没用——旧进程里没有新路由）。

## 五、标题是怎么认出来的（这里踩过一个大坑）

第一版写回**只按样式名**判标题（`Heading 1` / `标题 1`）。真实开题报告上实测的结果是：

* 15 个标题**一个都没认出来**——它们的样式名全是 `Normal`，靠段落自己的
  `w:outlineLvl` 表明层级（这是中文论文最常见的形态：学校模板只给一个 Normal 样式，
  标题靠大纲级别 + 手工加粗居中）；
* 于是 15 个标题被当成正文，统一改成"宋体 12 磅"；
* 格式检查器紧接着报出 7 条 `h1_font_size`、7 条 `h1_spacing`、1 条 `h2_cjk_font`——
  **越改越糟**，而总偏差数还是 113 条，看起来像"写回完全没生效"。

修法是**复用收稿阶段的同一套判定**（`app.parsing.docx_reader`：`outlineLvl` →
样式名/ID → 编号定义），保证"报偏差的判定"和"改偏差的判定"是同一个。
修正后真实文件：**113 条 → 69 条，能改的全部归零**。

同一个坑还牵出两件事：

* **标题加粗**原先只写在 `Heading 1/2/3` 样式上。手工排版的标题不套那些样式，
  于是 `h1_bold` 偏差**报得出、改不掉**。现在按 run 写 `w:b`/`w:bCs`。
* **段落标记的 `rPr`**（`w:pPr/w:rPr`）也必须一起改：它决定"光标停在这一段但不选
  任何文字"时 Word 显示什么，也参与格式检查器的解析链。只改 run 属性的话，
  检查器读到的仍是旧字体——**功能看着跑通了、报告也写"成功"，但偏差一条没减**。

**这个功能只能靠真实文档验证。** 合成夹具（`add_heading` 造的 `Heading 1`）
永远发现不了上面任何一条。所以 `tools/test_writeback.py` 里专门有一节
`[10] 手工排版的标题`，用 `Normal` + `w:outlineLvl` 造夹具，
断言"章标题没有被当成正文"和"可写回类偏差为 0"。

## 六、改哪些值？由规则文件决定，改与查共用一个尺子

目标值来自 `app/format/rules_default.yaml`（30 条规则里的**属性型**那部分）。
所以**改了规则，检查和写回一起变**——不会出现"检查按新标准报，写回按旧标准改"。

```yaml
- id: body_font_size      # 正文字号
  expected: 12.0
- id: body_line_spacing   # 行距（倍数或固定值）
  expected: {mode: multiple, value: 1.5}
- id: body_first_line_indent
  expected: {chars: 2.0}
- id: page_margin
  expected: {top_cm: 2.5, bottom_cm: 2.5, left_cm: 3.0, right_cm: 2.5}
```

**规则被停用（`enabled: false`）时，写回也一定跳过那一项。**
这条听着像废话，但第一版没做到：`take()` 拿到 `None` 后会静默沿用方案默认值，
于是"关掉字号检查"变成"把全文改成 12 磅"——**检查不报了，文件却被改了**。
现在停用的规则会把对应字段置为 `None`（=不改），并且有测试直接量文件确认
"停用的那一项真的没被改"（不只是断言清单里有这个名字）。

### `body_alignment`（正文两端对齐）默认是关的

多数学校确实要求正文两端对齐，但 **Word 的默认对齐就是左对齐**（段落里没有 `w:jc`）。
把它开着，几乎每一篇稿子都会因为没有显式写 `w:jc` 而被**逐段**报成 minor 偏差——
一堆噪声会把真正要紧的字体/字号问题淹掉。**误报比漏报更能毁掉工具可信度**，
所以这条默认只作为**可选项**存在：

* 默认：不检查、也不改（保持你文档的原样）；
* 学校明确要求时：把 `rules_default.yaml` 里 `body_alignment` 的 `enabled` 改成 `true`，
  检查与写回**同时**生效；
* 只想临时改一次：命令行加 `--align both`（这时会明确告诉你"这一项默认不检查，
  要复验请把规则打开"）。

## 七、排查：命令报"偏差没有减少"怎么办

先看 ④ 的两行分类：

* **可写回类是 0 条，文本类没变** → 正常。文本类（标点/空格/编号/题注缺失）
  本功能一条也改不了，用文本算子或人工处理。
* **可写回类还有剩余** → 把文件发我。可能的原因：
  * 标题既没有大纲级别也没有标题样式（"加粗+手工居中"的普通段落），
    工具无法与正文区分——报告里的"识别出 N 个标题"就是判定结果，先核对这个数；
  * 样式继承链特殊（字体写在 `theme1.xml` 的主题字体里、或 `basedOn` 链上有更强的样式）；
  * 段落带着更"深"的直接格式（如 run 里嵌了 `w:rStyle`）。
* **报告写失败** → 看是否"已还原备份"：原文没动，可直接重试或把错误信息发我。
